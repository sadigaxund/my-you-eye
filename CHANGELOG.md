## [2026.8.1] - 2026-08-22

### Changed

- **TreeView drop modes completed (#11 — issue now fully closed)** — `onMove` gains a `mode` parameter: `"into"` (folder target), `"before"`/`"after"` (sibling insertion). Drop zone comes from pointer position within the row (edges = insertion, middle = into for folders); illegal drops (self / own subtree) refused for every mode. Showcase drag demo handles all three. The flattened-tree virtualization recipe (aria-level/setsize/posinset fallback over `VirtualList`) is documented in `references/data-display.md`.

### Added

- **ColorField (#20)** — themed accent-color field: token-styled swatch trigger over the platform's native color input (accessible, zero reinvention), validated hex readout with danger-border on invalid text, optional preset swatch row. An in-app popover picker stays future work per the issue's own "nice-to-have" verdict.

- **Button `size="xs"` (#17)** — micro icon-only tier (20px, below `icon-sm`) for sidebar-header rows of New/Refresh/Collapse icons; composes with Tooltip like any Button.

- **TreeList (#26)** — the tree×table hybrid neither DataTable (flat) nor TreeView (label-only) covered: rows expand like a tree (TreeView's controlled/uncontrolled expansion model) while carrying typed columns rendered through CellType, with DataTable's column contract (`key`/`header`/`type`/`align`), indent elbow guides, sticky header, density, and controlled selection.
- **FileIcon (#10)** — generalized file/folder identity icon with zero icon-pack dependencies: the component owns the layout contract (square box, open/closed folder states, neutral built-in fallbacks); which icon a filename gets is injected via a consumer-supplied `resolve({ name, folder, open })` returning any ReactNode (Material pack, lucide glyphs, anything — rendered as-is, never tinted).

- **FindWidget (#4)** — engine-agnostic floating find/replace card: docks absolutely to a `position:relative` container's top-right corner without pushing content down, fully controlled (the consumer owns the search engine and state — CodeMirror's `@codemirror/search`, a plain scan, anything). Match-case/whole-word/regex toggles are real `aria-pressed` buttons; live "N of M" counter announces politely; Enter/Shift+Enter/Escape keyboard contract; replace row gated by the chevron and by the consumer's `replaceable` flag for read-only surfaces.

- **TreeView selection/rename/drag hooks (partial #11)** — additive upgrades: `label` widens to `ReactNode` and rows take a semantic `tone` (danger strikes through — deleted-file convention); controlled `selectedId`/`onSelect` decoupled from internal keyboard focus (`aria-selected` reports it, leaf rows select on click, Enter/Space selects); inline rename via `renamingId`/`onRenameCommit`/`onRenameCancel` (Enter/blur commits, Escape cancels); `draggable` + `onMove(sourceId, targetParentId)` for drop-onto-folder moves with self/descendant drops refused inside the tree. Omitting every prop is the read-only mode. Pure tree helpers extracted to `TreeView.tree-utils.ts`. Still open: between-row insertion-line drops ("before"/"after") and a documented flattened-tree virtualization recipe.

- **SidebarContainer (#13)** — persistent collapsible/resizable side-panel region (a layout counterpart to Drawer's transient overlay) with a controlled `width`/`collapsed` pair, a standard small-caps header row with trailing actions slot, and auto-collapse/restore thresholds. Its resize edge is #8's standalone `ResizeHandle`, and the handle stays mounted while collapsed so the panel always has a grab edge to restore by dragging. Paints from `--color-sidebar-*`.

- **SplitPane family (#8)** — recursively splittable pane grid: a `branch`/`direction`/`sizes` tree rendered as nested flex with a draggable divider between every pair of siblings; fractions clamp at 12% per side (`MIN_FRACTION`), double-click equalizes, arrow keys nudge ±8/32px. Two standalone primitives export from the same folder: `ResizeHandle` (pointer-capture drag mechanics reporting cumulative px deltas — reusable for any single resizable dimension without the pane tree) and `DockOverlay` (edge-aware primary-tinted drop-zone preview). Pure fraction math ships as `resizePair`. No ref forwarded by design (AGENTS §2.3 domain-props exception — a leaf-rooted tree has no single element).

- **TitleBar (#12) + EditorTabBar (#5)** — the remaining window-chrome pair. `TitleBar`: two-zone bar (identity + inline breadcrumb left, actions right), distinct from `Toolbar`, fixed-height with the breadcrumb folded into the identity cluster. `EditorTabBar`: closeable/draggable open-document strip — dirty dot beside (never replacing) the close button, italic preview tabs, within-bar drag reorder, documented `application/x-tab` dataTransfer payload for pane-docking, roving-tabindex arrow-key selection + Delete-to-close, trailing actions slot for an overflow trigger. Both paint from `--color-sidebar-*`.

- **App-chrome components on the sidebar namespace** (#6, #7): `ActivityBar` — vertical icon rail with an active left-edge accent bar (never a fill), per-item count badges, bottom-pinned footer item, labels in right-side tooltips; `StatusBar`/`StatusBarItem` — two-sided compact strip whose `tone` maps to the semantic token vocabulary Badge/Alert already use. Both paint exclusively from `--color-sidebar-*` (#27), codifying the persistent-chrome pattern.

- **CheckboxTree (#19)** — controlled tree picker with derived tri-state folders: given a `checked` set of FILE ids, folder checked/unchecked/indeterminate is computed fresh every render (never stored, so it can't drift), and toggling a folder applies to all descendants. Rows use the library's own `Checkbox` (Radix native mixed state); unchecked rows dim as a second cue. The checked-set owner stays external by contract.

- **VirtualList (#16)** — generic fixed-row-height windowed list composed on ScrollArea: an inner spacer sized to `items.length × rowHeight` keeps scrollbar thumb/track honest while only the current window plus overscan is mounted. `rowHeight` is a required prop (the caller reads it off its own layout tokens — no guessing). The windowing math ships DOM-free as `computeVirtualWindow`/`DEFAULT_OVERSCAN`, unit-testable without a renderer. No tree/list a11y semantics of its own — consumers add per-row roles inside `renderRow`.

- **ContextMenu (#3)** — pointer-position (right-click/long-press) menu on `@radix-ui/react-context-menu` (new direct dependency, pre-approved Radix per-component package), restyled with DropdownMenu's exact classes so the two families are visually indistinguishable. Items take `destructive` for danger-tinted focus; the `onCloseAutoFocus` suppress-refocus recipe is documented in a docblock for menus whose action may remove the triggering row.

- **SegmentedControl (#9)** — a single-choice segmented toggle on native radio inputs (radiogroup semantics + arrow-key model for free), distinct from `Tabs` (which is navigation bound to panels). Generic over the value's string type; per-segment real `disabled`; three sizes (`xs`/`sm`/`md`); `iconOnly` mode moves labels into tooltips. Active segment uses the theme's primary at 15% tint.

- **DropdownSubmenu (#21)** — `DropdownSubmenu`/`DropdownSubmenuTrigger`/`DropdownSubmenuContent` restyle Radix's Sub parts to be visually indistinguishable from the top-level menu. Same a11y model (arrow-right/hover opens, arrow-left/Escape closes, typeahead across levels); `disabled` on the trigger grays out an entire submenu at once — sanctioned over disabling every leaf item.

- **New components and gaps from the issue backlog** (#14, #18, #24, #25): `DiffStatChip` — chrome-free two-tone added/removed line counts sharing DiffBlock's success/danger tokens; `Input` gains `leading`/`trailing` slots (the ⌘K search-field composition); `SelectItem` renders children as one unwrappable inline-flex row so icon + label compose directly; `DataTable` gains `onRowClick` (never swallowing clicks on interactive descendants) and a trailing `renderActions` cell with `actionsHeader`/`actionsWidth` knobs.
- **Tree-shaking guarantee (#31)** — `"sideEffects": ["*.css"]` in package.json; per-component subpaths officially not supported (barrel + tier subpaths is the sanctioned path); consumer symbol-dump verification recipe documented in README.

- **Accessibility hardening pass over overlay/navigation primitives (#29)** — FormField now actually associates its label with the control (id injection), wires `aria-describedby` to the visible hint/error, sets `aria-invalid` + `data-invalid` on error, and marks error text `role="alert"`; Input/Textarea respond to a universal `data-[invalid]` styling hook; Dialog's built-in close button gets an accessible name and a focus-visible ring, and dialog content contains overscroll; `.dark` sets `color-scheme: dark` so native inputs/scrollbars render dark; a global `prefers-reduced-motion` guard collapses all ui-tier CSS animation/transition. Radix-provided mechanics (menu trigger ARIA + arrow/Home/End/Escape traversal, dialog focus trap/restore, tabs roving tabindex) verified and documented in `references/rules/forms.md`, including the required-`DialogTitle` sr-only fallback.

- **Dedicated sidebar token namespace (#27)** — seven new `--color-sidebar-*` tokens (`sidebar`, `sidebar-fg`, `sidebar-border`, `sidebar-item-hover`, `sidebar-item-active`, `sidebar-badge`, `sidebar-badge-fg`) let app-shell chrome (sidebars, activity rails, status bars) be themed independently of page surfaces — shadcn's `--sidebar-*` precedent. Base values alias each theme's own opaque surface roles, so every theme looks identical to before; check-themes now requires all themes (light + dark) to state the family explicitly, with opaque item-hover/active values in glass/frosted where the generic surface family is translucent. check-contrast gained four sidebar pairs (panel text on resting/hovered/active rows, badge text on its accent) and resolves `var()` alias chains; SKILL.md documents the namespace.

- **SKILL.md architecture upgrade (#30)** — the distributed skill adopts shadcn's proven layout while staying lean: a new **Step 0 "load your context"** section (manifest as ground truth, check-installed-first rule covering local component inventories, precedence of the consumer's own repo law), a **need→component quick-lookup table** complementing the playbooks, and **consent gates** (ask before: new dependencies, forking component source, multi-file structural changes, inventing patterns). Domain detail moved to four new `references/rules/*.md` files — `styling`, `forms`, `composition`, `icons` — each written as Incorrect/Correct code pairs; SKILL.md's "rules that matter most" now points at them. `my-you-eye init` copies reference subdirectories so `rules/` lands in consuming projects.

- **Skills pack — a curated, trust-ranked index of the frontend agent-skill ecosystem, shipped and operational.** Two new reference docs ride the existing `init`/`sync` pipeline: `references/skills-index.md` (the router — precedence chain, per-source "use when" tables, a task-routing matrix, and a conflicts register) and `references/skills-analysis.md` (the provenance/trust record — tier ranking, inventories, concerns, verdicts for every source). The library adopts the system internally too (`npm run skills:update` / `skills:update:latest`) — all 15 sources pinned at first run.

## [0.6.0] - 2026-08-15

### Fixed

- **The Comparison header-separator artifact — for real this time.** The half-rendered line between a code pane's header and body survived every previous fix because none touched its actual cause: the 1px `border-b` was rasterizing against fractional-pixel boundaries — the wipe's percentage `clip-path` cuts an antialiased vertical seam through the border row, and columns mode's `1fr` grid tracks are themselves non-integer widths. `Comparison` now measures its container (ResizeObserver) and pixel-snaps both: the wipe clip is an integer-px inset and, while a reveal is active, the two panes are laid out at explicit integer pixel widths. Percentage fallback covers the first unmeasured frame.
- **CodeBlock's copy button works on plain-http origins.** It silently no-oped wherever `navigator.clipboard` is unavailable (any non-secure context — e.g. a LAN dev server) and swallowed rejections. It now falls back to the textarea/`execCommand` path and shows a visible "Copy failed" state when both routes fail.
- **Presenter no longer advances on stage clicks.** Any mouseup — including the end of a canvas drag — used to fire `next()`, making it impossible to pan a live diagram mid-presentation. Advancing is now explicit only: Space/arrows and the chrome's Prev/Next buttons.
- **CodeScene is watchable.** Camera moves and diff cross-fades derived their entire duration from narration length, so a terse `say` produced sub-second pans; and out-of-focus dimming reused the shared 0.4 muted token. Code-scene steps now floor at 1.5s with the transition window clamped to 0.6–1.2s (`codeTransitionFrames`), the camera holds-then-moves inside each step instead of drifting for its whole span, and focus dimming uses a new dedicated `--opacity-focus-dim` token (0.25 base, 0.5 in brutal, defined across every theme and enforced by check-themes).
- **Showcase page-nav polish**: prev/next cards are equal width with truncation, and the hover underline is gone — `no-underline` could never beat `hover:underline` on specificity, so `Link` gained a proper `underline` boolean axis (default true) used by the nav and TOC.

### Changed

- **Terminal output is plain tokenized text.** Output entries used to mount a full `CodeBlock` inside the frame — its own border, language badge, hover copy button, and a nested scroll region. Output now renders through the tokenizer directly as wrapped mono lines that inherit the terminal's scheme.
- **The API reference panel was redesigned**: one surface panel holding a Variants block and a stacked, `divide-y` prop list — name, wrapping type chip, a default chip only when a default exists, and readable descriptions — replacing the four-column table whose Default column was mostly dashes and whose Type column crushed everything else.
- **Showcase prose got a humanizer pass**: 124 entry/demo descriptions rewritten to plain, direct sentences (em dashes and AI-pattern phrasing removed, every factual claim kept); page descriptions and demo blurbs now run to an 80ch measure instead of stopping at 65ch mid-column; the import line on every page is syntax-highlighted via CodeBlock's `bare` mode.

## [0.5.0] - 2026-08-15

### Fixed

- **`CodeScene` no longer resizes while typing.** The typed path fed a progressively-sliced source into `CodeBlock`, so gutter row count, block width and centered position all shifted per character — and the camera's ResizeObserver re-targeted on every resize, compounding the jitter. Typed steps now render a hidden ghost `CodeBlock` carrying the final source in the same grid cell (TypeText's `preserveLayout` pattern), with the untyped tail's newlines preserved so the line count is final from frame 1. The box is now rock-steady; only text content changes.
- **`CodeDiff`/`DiffBlock` word-diff reads calmly instead of randomly.** The tokenizer makes every punctuation char its own token, so the LCS trivially matched stray parens/spaces across unrelated text, scattering tiny highlight boxes. New `DiffBlock.refine.ts` post-processing (shared by `DiffBlock` unified/split and `CodeDiff`): noise unchanged-runs (≤2 chars or pure punctuation/whitespace) wedged between changed runs are absorbed; sub-2-char changed runs are dropped unless they're the line's only change; and a line more than 55% changed falls back to the whole-line row treatment instead of per-segment boxes. Measured on the fixtures: one line went 9 boxes → 2.
- **`CompareScene` wipe no longer paints a label badge over the `CodeBlock` header.** For `content: "code"` panes the same label was rendered twice — in the CodeBlock's own header AND as `Comparison`'s absolutely-positioned z-10 wipe badge sitting exactly in the header band. Code panes now rely on their CodeBlock header alone (per side, so mixed code-vs-image scenes keep the non-code badge), and the doubled inner border is suppressed.
- **`DiagramScene` fits, breathes, and shows its group labels.** Three root causes fixed: node pitch was tight (layer gap 3 → 5 grid units, sibling gap widened); the scene only centered and never scaled, so anything larger than the canvas rendered cropped at zoom 1 (new `fitScale` — Camera's `fitZoom` reused — with 2-grid-unit padding, wired through `Canvas` as a controlled zoom that re-fits on resize, never upscaling); and the group label chip was inset into the band where the topmost member node paints over it (`labelPlacement="outside-top"`, with the label band reserved in the bounds so the fit doesn't crop it). `Canvas`'s ctrl+wheel now routes through the controlled-aware zoom setter so controlled zoom doesn't snap back.
- **`WalkthroughScene`'s spotlight no longer pops off at a step boundary.** `Spotlight`'s dim was a pure product of the current step's props, so the frame the step index advanced, a 0.6-dimmed overlay snapped to clear. New `spotlightPlan()` ramps the dim out over the last 20% of the spotlighted step (capped at 12 frames) and interpolates rects between consecutive spotlit steps, anchored so progress never restarts mid-run. `Spotlight` itself stays a pure function.
- **Showcase previews no longer melt textured themes.** Every `MotionPreview` ran its own per-instance rAF loop with two React state updates per tick, forever, with no offscreen or tab-visibility gating — up to 5 concurrent loops per page, each repainting through comic/metallic page textures or glass/frosted `backdrop-filter` layers. Now: `DomDriver`'s loop fully stops while paused (a parked preview costs zero), React commits are gated on the rounded frame changing (2–4× fewer renders while playing), a single shared IntersectionObserver + `visibilitychange` listener pauses previews that are off-screen or in a hidden tab (never resurrecting a user-paused one), preview stages and demo cards get `contain: paint`, and `prefers-reduced-motion` is now honored live via a change listener rather than read once at mount.

### Changed

- **`Terminal` is text-only inside the frame** (owner decision). Exit codes render as a plain monospace status line (`✓ exit 0` success / `✗ exit N` danger) instead of a `Badge` pill; in-progress entries render a braille glyph + label instead of the `Spinner` component; output keeps CodeBlock's ANSI-plausible syntax coloring. API unchanged plus a new `TerminalEntry.spinnerGlyph?` — `TerminalScene` cycles the braille set from the current frame (~10 glyphs/s), so spinners animate deterministically in both the live presenter and MP4 renders.
- **The showcase now reads like component-library docs.** Every page: a header with group badge, readable-width description and a copyable derived import line; uniform demo cards (every preview in the same textured panel — the old split where extracted-source demos lost their panel is gone) with anchored headings, hover `#` links and an in-card Code toggle; an auto-generated API reference from `components.json` (variant axes as chips with defaults marked, a Prop/Type/Default/Description table, inherited-interfaces footnote); an "On this page" TOC for long pages; prev/next navigation; and two-level deep links (`#button--sizes` opens the page and scrolls to the card). Built entirely from the library's own components. `WalkthroughScene`'s placeholder screenshot was redrawn as a recognizable product UI (nav, sidebar, settings form) with before/after variants, and its demo steps now land on real drawn elements.
- **Release hygiene**: annotated tags are now SSH-signed (`tag.gpgsign`), and `npm publish` runs with `--provenance` (the workflow already had `id-token: write`), so GitHub tags verify and npm shows a provenance attestation. The `repository.url` was normalized to the `git+https` form provenance validates against.

## [0.4.0] - 2026-08-15

- **The full type surface at the package root.** Every component's `*Props` type and every CVA `*Variants` object is now re-exported from `"my-you-eye"` (206 → 365 root exports). ### Added (previous round)

- **Arrowhead shapes, and per-shape line trimming** (`src/ui/connection-line/arrowheads.tsx`) — `arrowhead` takes `"triangle" | "open" | "circle" | "hollow-circle" | "diamond" | "hollow-diamond" | "bar" | "crow"` as well as `true`. Each shape declares how far the ROUTE must stop short of the endpoint, and the stroke is trimmed to exactly that: a solid head absorbs the line and ends ~1px inside it (a stroke and a fill that merely touch show a hairline seam under antialiasing), while an open head is drawn *around* the line and trims nothing. `Annotation` shares the same table, including for its `pin` marker, which sits *on* the target and so needs the leader to stop at its ring.

(The reported texture lag is therefore still unexplained — see TODO.md.)

### Fixed

- **Substring highlights sat two characters to the left of the text they named.** The overlay anchored each rect at the line div's `offsetLeft` — its *border-box* left — but that div carries `px-panel`, so the first character actually begins 16px (≈2.2 monospace characters) further in. Every `highlightRanges` example in the showcase was therefore drawing a correctly-*sized* box over the wrong span, which is the other half of "highlighting random incomprehensible parts of the code": the `match` API fixed which characters were asked for, this fixes where they were drawn. The padding is read from computed style rather than hardcoded, since it's a theme token.
- **The `CodeScene` "Playing" demo was unreadable** (owner: "the 'Playing' scene is weird, i dont understand what it tries to convey"), for three independent reasons. A changed diff row *cross*-faded two absolutely-stacked layers, painting two different monospace strings onto the same pixels — mid-transition a row read `let sum = 0;bl = items.reduce(…`. The two fades no longer overlap, which costs one blank beat and buys a row that is legible on every frame. Separately the diff ran for the step's entire duration, so the rewritten source was never shown as ordinary code and the step's own `focus`/highlight had nothing to land on; it now settles into a plain `CodeBlock` partway through. And every camera keyframe was framed at the *container's* full width, which pins `min(W/w, H/h)` to 1 — the camera could only ever pan, never zoom, so a "focus lines 2–5" step looked identical to the wide shot before it. The focus rect now comes from the line elements themselves, with a zoom ceiling so leaning in doesn't crop the file away.
- **`Terminal`'s `rows` was a cap, not a height.** It set `max-height`, so the box still started short and grew line by line until it hit the ceiling — the exact behaviour `rows` exists to prevent (owner: "I dont like how the terminal's size gets bigger whenever a new line is added, I want to see a constant height terminal that does not change or move"). It is now an exact height — measured line-height × `rows`, plus the body's own measured padding — from the first frame onward, with the transcript scrolling underneath it. `flex-1` is dropped in that case, because a `0%` flex-basis wins over `height` in a column flex container and silently restored content sizing. `TerminalScene` now defaults to 12 rows: a scene draws into a fixed video frame, where a growing box makes the whole composition jump.
- **The `after` pane's header separator still vanished mid-reveal.** The previous round synchronised the fade across the whole column, which was the wrong fix: partial alpha *itself* is the problem, because a 1px `border-border` hairline drops below the eye's threshold long before the text beside it does. `Comparison` now reveals the after column with a left-to-right `clip-path` instead of an opacity ramp, so every pixel it draws is drawn at full strength.
- **Numeric `CellType`s mixed two alignments in one column.** The number/unit grid put the `1fr` on the *number*, which right-aligns a suffix correctly but tears a prefix apart — `$` pinned to the cell's left edge with the digits flung to the right (owner: "Currency type has dollar sign on the left, and the value on the right, is it purposely done?"). Types with no unit at all (`number`, `duration`, `signed`) skipped the grid entirely and rendered left-aligned. An empty leading `1fr` spacer gives every numeric type the same right-aligned behaviour and keeps a prefix glued to its digits.
- **`Annotation`'s arrowheads rendered in the page's text colour.** Every shape in `ARROWHEADS` paints with the `fill="currentColor"` *attribute*, which resolves against the inherited `color` property — a `fill-primary` class on the wrapping `<g>` sets that `<g>`'s own fill and is ignored by a child declaring its own. So the head came out near-black next to a correctly-accented leader line (owner: "why does triangle arrowheads … have smaller black arrowheads within them"). `ConnectionPath` already coloured its head with `text-*`; `Annotation` does now too.
- **The `+`/`-` markers and line numbers in a diff sat high in their rows.** A diff row is a flex container, and the gutter cells carried `text-xs`'s 16px line box against the code column's `leading-relaxed` 19.5px. A short cell stretches to the row's height but paints its glyph at the top of that box, so the markers rode ~2px above the code. Matching the line-height puts every cell on one shared baseline, which vertical centring would only have approximated.
- **Every DiagramScene rendered its nodes piled in the top-left corner.** `layered()`/`grid()` used the *gap* as the whole node PITCH — a position was `index * gap`, with the node's own extent never added. At the default 4-cell layer gap (64px) against a 12-cell-wide diagram node (192px), consecutive layers overlapped by 128px and an entire graph collapsed into roughly one node's worth of space. Every option there is named a *gap*, so it is one now: pitch is `nodeSize + gap`, with the footprint passed in. Crossing reduction is unaffected (it depends on ordering, not spacing) and `prove-layout-crossings.mjs` still reports 13 → 1. Separately, nothing centred the result — layout necessarily emits origin-anchored coordinates — so `centerOffset`/`shiftRects` centre content in the measured canvas, applied to the rects themselves rather than a wrapper transform so edges, flow tokens and annotation callouts stay in agreement.
- **Bezier edges kinked into an S on every short span.** The control handle was `max(dist * 0.4, 30)`; on a 60px edge that floor is *half the distance*, pushed out along two different normals. The handle now scales with how much turning the curve actually has to do, derived from the same dot products the anchor selection scores with — near-collinear normals get short handles and a nearly straight line, perpendicular ones get long handles and a properly round corner. Sampling is adaptive too, since gapped/trimmed beziers render as the sampled polyline.
- **`DomDriver` auto-paused forward playback before it ever moved.** The first tick after mount (or any `play()`/`seek()`, which reset `lastTsRef`) has no previous timestamp, so `dtSeconds` is 0 and `next = frame + 0`. Starting at frame 0 that satisfies the `next <= 0` boundary test, which the driver reads as "played backward into 0, stop" and sets `playing = false`. Masked everywhere `loop` is true (the pause branch is non-loop-only), which is every `MotionPreview` demo — `Presenter` is the one consumer using `loop=false`, so every scene it showed froze on its opacity-0 entrance frame. Owner: "the controls work fine, but not sure what Im looking at, I dont really see the scenes."
- **`highlightRanges` took character offsets nobody could verify.** `{ line: 2, start: 6, end: 18 }` cannot be checked by eye, so in practice the numbers drifted and landed mid-token (owner: "highlighting random incomprehensible parts of the code... I assume it might be because of the positional arguments it takes"). It now takes `match: string | RegExp` with an `occurrence` selector; text that isn't on the line highlights NOTHING rather than the wrong span. Offsets remain as an escape hatch.
- **Four showcase demos silently lost their Preview/Code tabs.** `extractDemoSource` rejected `render: () => { … }` block bodies outright, and `DemoSection` falls back to a plain box whenever extraction returns null — so any demo needing a local `const` looked structurally different from every other demo on its page.
- **A colour utility naming a token that doesn't exist is invisible to every check.** `bg-info/70` shipped in Timeline's span bars; there is no `--color-info` (StatusDot's own `info` variant resolves to `bg-primary`), so Tailwind emitted no rule and the bar simply wasn't there. tsc, eslint and Tailwind itself are all silent. New `check-tokens.mjs` compares source against the BUILT stylesheet — Tailwind emits a rule per utility it resolves, so a literal class with no matching rule is by construction one Tailwind rejected. That needs no model of Tailwind's namespace (a first attempt that enumerated prefixes and palettes produced ~40 false positives) and cannot drift. Verified in both directions, including that it fails on the original bug — which it did not, at first: `active: "bg-info/70"` is a single-word literal, and those had been skipped as unverifiable.
- **`GraphNode` row ports rendered as vertical lines** — see below; and `Port` gained `mount` to fix it.
- **`npm run validate` never typechecked anything.** Its first step was `tsc --noEmit`, but the root `tsconfig.json` is a solution file (`"files": []` plus project references), so that command checked nothing and exited 0. The only real typecheck was `tsc -b` inside `build`, which `validate` doesn't run — `build:lib` is tsup and `vite build` doesn't typecheck either. Every type error in `src/` had been invisible for as long as the script looked like that. Now `tsc -b --force`, with `--force` because the incremental cache will happily report success for a project it believes unchanged, which is the same silent pass in a different shape. This surfaced 15 pre-existing errors, all now fixed: `Tuner.tsx` used three state types it never imported; `Tuner.Preview.tsx` imported `React` as a named export of `"react"`; a `Presets.tsx` preset omitted a required field; `ChartFrame` declared `children` required though `loading`/`empty` short-circuit before calling it; `CodeBlock.highlight.tsx` annotated returns as `JSX.Element` under a config with no global JSX namespace; and the showcase held its texture in `useState("theme")` (inferred `string`) and passed it through four components typed `texture: string`, so the `TexturedSurface` union was unchecked at every one of those call sites.
- **Edges attached to nothing.** Owner: "it feels like you drew the components and slapped lines on top of it." An edge could only be specified as two *points*, so callers passed node centres and the stroke ran into each box. `anchors.ts` lets `from`/`to` be a shape instead: eight anchors per rect (four side centres, four corners), chosen by a cost that rewards leaving and arriving along the side's own outward normal rather than by shortest distance — shortest alone picks corners almost every time, which is exactly what reads as accidental. The chosen normal flows into the path math, so a bezier leaves and arrives perpendicular to the side it touches instead of always horizontally. `SequenceDiagram` was the reported example: messages ran lane-centre to lane-centre straight through the 12px activation bars, so an arrowhead landed *inside* the bar it pointed at.
- **Arrowheads penetrated their target.** The polygon had its base at the local origin and its tip 8px past it, so `translate(to)` put the tip 8px beyond `to` — i.e. inside the node, since `to` is a point on its border. Flipped to tip-at-origin and shared as `ARROWHEAD_POINTS` so `ConnectionPath` and `Annotation` can't drift.
- **Edge labels sat off the line.** Two independent causes: the badge was an inline box in a tightly-fitted `foreignObject`, so the anonymous line box's strut (inherited font metrics, not the badge's own `text-xs leading-none`) pushed it below the stroke; and its `x` was clamped into the route's x-bbox, shoving it off-centre on short or steep edges. Now a slack box centred on the anchor with flex centring — exact on first paint, before any measurement lands. Separately, the stroke gap under the label ran `halfWidth + 6` along the arc, overshooting the badge by 6px each side and biting a visible notch out of the line (owner: "why does the label delete or cover the part of the lines"), and on a steep edge used the half-*width* where the badge's *height* is what covers the stroke. It's a ray/box intersection against the badge's own border now.
- **`GraphNode`'s row ports rendered as vertical lines.** Owner: "is the port on that graph example supposed to look like a vertical line? I did not see that variation in the Ports showcase." It isn't a variation. The node's root carries both `overflow-hidden` and `contain: [layout paint]`, neither escapable by a descendant, and the socket bulged *outward* — so its entire visible half was clipped away, leaving only the flat chord's 2px stroke. New `Port` `mount` prop (`"outward"` default / `"inward"`) inverts the arc; row ports mount inward. The showcase demo for it uses a real clipping ancestor rather than a dashed rule standing in for one, because the existing socket demo cannot reproduce the bug.
- **`Timeline` rescaled every lane independently.** Each lane computed its own min/max, so two events with the same `at` in different lanes landed at different x positions and a lane whose events shared one `at` stretched that instant across the full width — which defeats the only reason `lane` exists. One scale over all events now. Also, point events are positioned proportionally to `at` and the label is by far the widest part of an event, so close neighbours always overlapped; `labelPlacement="stagger"` (the new default) alternates labels above and below the rule, making adjacent collisions impossible without measuring anything.
- **`Markdown` produced live `javascript:` links.** Link targets were passed straight to `href`, so `[x](javascript:alert(1))` rendered an executable URL — React only *warns* about those, it still sets the attribute, so nothing in the stack was stopping it. Targets are now scheme-checked (http/https/mailto/tel, plus relative and anchor links), and anything else renders with no href at all. In the same file, `escapeHtml` was applied to strings then passed as JSX *text children*, which React escapes again — so "Tom & Jerry" displayed as the literal "Tom &amp;amp; Jerry". Verified with `renderToStaticMarkup` and removed; React's own escaping is the correct and only layer.
- **`Spotlight` rendered nothing at all in two of its three demos.** Its root was a block box with `overflow: hidden` whose children were all absolutely positioned — a diagram's nodes, a dashboard's cards — so it had no normal-flow content to derive a height from, collapsed to 0px, and then clipped its own (correctly positioned) scrim and children out of existence. Measured live in the showcase: 0px tall before, 64px and 176px after. It now defaults to `w-full h-full`, which is a no-op for normal-flow content because `height: 100%` against an auto-height parent resolves to `auto` — the one demo that did render is unchanged at 144px.
- **`Pulse` didn't start or end at rest.** The wave was `sin(t·2π)` rescaled into [0,1], which sits at 0.5 — already mid-breath — at both ends of every period and only reaches true rest a quarter-period late. A finite `loop` therefore settled on a different value than it started from, reading as a snap. It's one hump per period now, `sin(t·π)`, which is 0 at both ends and peaks in the middle.
- **`Shake`'s first frame was already displaced.** Its oscillation term is naturally 0 at frame 0, but the jitter term is raw noise with no such property, and it was scaled only by `decay` — which is at full strength at progress 0. Jitter is now gated by the eased phase as well, so both terms start at exactly 0.
- **`Camera` moved at raw constant speed** between keyframes, the last unstyled movement curve in the motion tier. Legs are now shaped by the same easing/spring vocabulary every other primitive uses, extracted into `core/legEase.ts` so `Camera` and `Cursor` share one definition instead of each carrying a copy. It pins only the two endpoints, matching `useProgress` — clamping the middle to [0,1] (as the extracted copy did) silently flattens `snappy` and `bouncy` into the same critically-damped curve.
- **The showcase frame readout printed a raw float** (`40.99800000000001/120`). `DomDriver` reports the unrounded rAF-accumulated frame deliberately, since sub-frame precision is useful to a logic consumer like the Presenter's seek comparison; `MotionPreview` is a display, so it rounds at that boundary. - **`Cursor`'s hand glyph was unreadable at 18px**, where a single intricate outline collapses into a blob. Rebuilt from separated bold primitives — one extended finger, two folded knuckles, a palm — with real gaps between them. `Cursor` also gains a `children` escape hatch for a fully custom pointer, centred on the tracked position since an arbitrary node has no predictable tip.
- **`Spotlight`'s scrim inverted in every dark theme.** It dimmed with `--color-fg`, which is near-black in the light palette but flips to `oklch(0.95 …)` in `dark`, `neon` and the rest — so the "dim everything except this" overlay *lightened* the surroundings. Worst case approaches `sqrt(2)`, so the radius now sweeps to 142%.
